# BauTex Design — каталог и визуализация обоев

**BauTex Design** — прототип full-stack веб-приложения для выбора обоев и их предварительной визуализации в интерьере. Пользователь может изучить каталог, подобрать цвет и фактуру, сохранить товары в избранное или корзину, а затем загрузить фото комнаты и увидеть результат наложения обоев.

## ✨ Что реализовано

### Для пользователя

- каталог обоев с коллекциями, карточками товаров, вариантами цветов и выбором количества;
- корзина, избранное, оформление заказов и личный кабинет;
- регистрация и вход по JWT;
- интерактивная визуализация: фото комнаты → маска стены → текстура и цвет обоев;
- ручная корректировка маски кистью, если автоматическая сегментация неточна;
- AI-чат, карта точек продаж, страницы инструкций и отзывов.

### Для администратора

- управление каталогом и цветами товаров;
- просмотр пользователей, заказов и обращений;
- изменение статусов заказов.

## 🧰 Стек

- **Клиентская часть:** React 19, TypeScript, Redux Toolkit, React Router, Webpack.
- **Серверная часть:** Node.js, Express, SQLite, JWT, Multer.
- **ML-сервис:** FastAPI, PyTorch, Hugging Face Transformers, SegFormer B0 и Pillow.
- **Инфраструктура:** Docker Compose; отдельные контейнеры для frontend, API и ML.

Самый быстрый способ запустить все сервисы:

## Публикация фронтенда на GitHub Pages

Сайт публикуется по адресу **https://aminulik.github.io/bautex-design/**.

Собрать и опубликовать:

```bash
npm run deploy
```

Команда собирает `dist/` и выкладывает его в ветку `gh-pages` этого же репозитория.
Ветка `main` остаётся с одними исходниками — собранные файлы в неё не попадают.
В настройках репозитория Pages должны быть переключены на ветку `gh-pages`, папка `/ (root)`.

Базовый путь задаётся переменной `PUBLIC_PATH`, из неё же берётся `basename` роутера —
поэтому пути к ассетам и маршруты не могут разъехаться:

- по умолчанию `/bautex-design/` — project page, как сейчас;
- `PUBLIC_PATH=/` — если сайт понадобится отдавать из корня домена.

Рядом с `index.html` кладётся `404.html` с тем же содержимым: без него GitHub Pages
отдаёт ошибку на прямых ссылках вида `/catalog` и при обновлении страницы.

Статическая сборка отдаётся без Express и ML-сервиса. Пока `REACT_APP_API_URL` не задан,
приложение считает себя демо-версией и показывает плашку на страницах, которым нужен
бэкенд: вход, оформление заказа, AI-чат, визуализация и ML-метрики. Каталог, коллекции,
избранное, отзывы и справочные страницы при этом работают полностью — они опираются на
`src/data/catalogItems.ts` и `localStorage`.

## Запуск серверной части

Сервер реализован на Express и находится в директории `server`.

Установите серверные зависимости:

```bash
npm --prefix server install
```

Создайте `server/.env` на основе `server/.env.example`, затем выполните:

```bash
npm run server:start
```

Для разработки с автоматической перезагрузкой:

```bash
npm run server:dev
```

Стандартные адреса:

- клиентская часть: `http://localhost:3001`;
- серверная часть: `http://localhost:3003`;
- health-check: `http://localhost:3003/health`.

## Локальный ML-сервис SegFormer

Для визуализации используется локальный ML-сервис на FastAPI:

```text
React -> Express /api/visualize -> FastAPI SegFormer -> wall mask -> wallpaper composite
```

Установите Python-зависимости:

```bash
npm run ml:install
```

Запустите ML-сервис на `http://localhost:8000`:

```bash
npm run ml:start
```

Добавьте в `server/.env` следующую переменную и перезапустите сервер:

```env
SEGFORMER_API_URL=http://localhost:8000/segment/wall
```

При первом обращении ML-сервис загружает модель nvidia/segformer-b0-finetuned-ade-512-512, поэтому первый запрос может обрабатываться дольше последующих.

Чтобы оценить качество сегментации на локальном тестовом наборе:

```bash
npm run ml:evaluate
```

Поместите исходные фото в `test_data/segmentation/images`, а подготовленные вручную маски стен — в `test_data/segmentation/masks_gt`.

## Запуск через Docker

Чтобы запустить клиентскую часть, API и ML-сервис одной командой:

```bash
npm run docker:up
```

Запустить демонстрационное окружение:

```bash
npm run demo:up
```

Остановить контейнеры:

```bash
npm run docker:down
```

Посмотреть логи:

```bash
npm run docker:logs
```

Проверить состояние контейнеров:

```bash
npm run docker:ps
```

Удалить контейнеры и локальные тома:

```bash
npm run docker:clean
```

Используемые порты: клиентская часть — `3001`, API — `3003`, ML-сервис — `8000`.

В [DEMO.md](./DEMO.md) описаны сценарий демонстрации, тестовые учётные записи и структура ML-датасета.

## Переменные окружения

Не добавляйте локальные `.env`-файлы в Git. В качестве шаблона для сервера используйте `server/.env.example`.

Основные серверные переменные:

- `PORT`
- `FRONTEND_ORIGIN`
- `JWT_SECRET`
- `ADMIN_EMAIL`
- `ADMIN_PASSWORD`
- Полный список поддерживаемых переменных и примеры значений находятся в server/.env.example.

## Файлы, не сохраняемые в репозитории

- `dist/`, `build/`
- `.idea/`, `.vscode/`
- `.env`, `server/.env`
- базы данных SQLite, например `server/orders.db`;
- runtime-каталоги backend: `server/debug/`, `server/results/`,
  `server/uploads/`, `server/temp/`;
- `node_modules/` в корне проекта и в `server`.

## Примечание о ML-части

Основной автоматический метод сегментации — локальная модель SegFormer B0, дообученная на ADE20K. Она используется для построения маски стены на загруженной фотографии.

В проекте также предусмотрены:

- эвристическая сегментация при недоступности ML-сервиса;
- ручная коррекция маски;
- тестовый набор изображений и эталонных масок;
- расчёт IoU, Dice, Precision и Recall.

Для теоретического сравнения можно использовать:

- U-Net;
- DeepLabV3+;
- PSPNet;
- SAM;
- Mask2Former;
- OneFormer;
- YOLOv8-seg.
